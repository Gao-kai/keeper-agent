# 知识库查询 —— 答案生成节点

## 1. 任务目标

本节课将实现知识库查询流程中的 **答案生成节点**（`answer_output`）。

该节点是整个查询流程的终点，负责将检索到的上下文、知识图谱关系组装成提示词，调用 LLM 生成最终答案。

**学完本节你将掌握：**
- LLM 提示词工程的最佳实践
- 字符预算控制（Context Budget）技术
- 多源上下文（文档 + 图谱）的格式化与组装
- LLM 非流式调用与降级处理

> **注意**：流式输出（SSE 推送）、历史对话格式化、MongoDB 历史记录持久化将在第二天讲解，本章暂不涉及。

## 2. 核心概念扫盲

### 2.1 为什么答案生成是最复杂的节点？

答案生成节点需要整合整个查询流程的所有结果：

```
  ┌──────────────────────────────────────────────────────────┐
  │                     answer_output                        │
  │                                                          │
  │   输入汇总：                                              │
  │   ├── reranked_docs    重排序后的文档（RRF + Rerank）      │
  │   ├── kg_triples       知识图谱三元组关系                  │
  │   ├── item_names       已确认的商品名                      │
  │   ├── rewritten_query  重写后的用户问题                    │
  │   └── history          历史对话（TODO 第二天）              │
  │                                                          │
  │   处理流程：                                              │
  │   格式化各项输入 → 组装提示词 → 调用 LLM → 输出答案        │
  └──────────────────────────────────────────────────────────┘
```

前面所有节点（商品确认、向量检索、HyDE、知识图谱、RRF、Rerank）的成果最终都汇聚到这里，由一个提示词模板统一组装后交给 LLM 生成答案。提示词的质量直接决定答案的质量。

每个区块为 LLM 提供不同维度的信息：参考内容是核心证据，图谱关系补充结构化知识，商品名限定回答范围，用户问题明确回答目标。

### 2.3 字符预算控制

LLM 有输入长度限制（token 上限），需要控制提示词总长度：

```python
char_budget = config.max_context_chars  # 默认 12000

# 依次分配给各区块，优先级递减
context_str, char_budget = self._format_reranked_docs(docs, char_budget)   # 文档优先
# TODO（第二天）：history_str, char_budget = self._format_chat_history(...)  # 历史次之
graph_str, char_budget = self._format_kg_triples(triples, char_budget)     # 图谱最后
```

**预算分配策略：**

| 优先级 | 区块 | 理由 |
|--------|------|------|
| 最高 | 检索文档 | 核心参考内容，直接决定答案质量 |
| 次之 | 历史对话（TODO 第二天） | 理解多轮对话上下文 |
| 最低 | 图谱关系 | 补充结构化信息，非必需 |

**工作机制**：每个格式化方法消耗一部分预算后，将剩余预算传给下一个方法。如果检索文档就占满了 12000 字符，图谱关系就会被截断为空。

##### Step 2: 格式化检索文档

将重排序后的文档格式化为提示词文本，带字符预算控制：

```python
def _format_reranked_docs(self, reranked_docs: List[Dict], char_budget: int) -> Tuple[str, int]:
    formatted_lines = []
    used_chars = 0

    for idx, doc in enumerate(reranked_docs, 1):
        # 1. 提取文档内容
        content = doc.get("content", "").strip()
        if not content:
            continue

        # 2. 构建元信息标签
        meta_tags = [f"[{idx}]"]
        for field, template in [
            ("source", "[source={}]"),
            ("chunk_id", "[chunk_id={}]"),
            ("url", "[url={}]"),
            ("title", "[title={}]"),
        ]:
            field_value = str(doc.get(field, "")).strip()
            if field_value:
                meta_tags.append(template.format(field_value))

        # 3. 添加相关性分数
        relevance_score = doc.get("score")
        if relevance_score is not None:
            meta_tags.append(f"[score={float(relevance_score):.4f}]")

        # 4. 拼接元信息和正文
        doc_entry = " ".join(meta_tags) + "\n" + content

        # 5. 检查预算
        if used_chars + len(doc_entry) > char_budget:
            break

        formatted_lines.append(doc_entry)
        used_chars += len(doc_entry) + 2  # +2 是 "\n\n" 分隔符

    return "\n\n".join(formatted_lines), char_budget - used_chars
```

**格式化结果示例：**

```
[1] [source=local] [chunk_id=chunk_001] [title=操作指导] [score=5.0600]
测量直流电压时，将旋钮转到DCV档位，红表笔接VΩmA孔，黑表笔接COM孔，然后将表笔接触被测电路两端。

[2] [source=local] [chunk_id=chunk_002] [title=安全手册] [score=3.9600]
注意：测量前请确认档位与量程，避免误接导致损坏或触电。
```

> **为什么元信息标签要传给 LLM？** 让 LLM 知道每篇文档的来源、标题、相关性分数，帮助它判断哪些内容更可信，生成答案时可以优先参考高分文档。

> **`used_chars += len(doc_entry) + 2` 中的 +2**：最后拼接时用 `"\n\n".join()`，每两篇文档之间会插入两个换行符，预算计算时要把这 2 个字符也算进去。

##### Step 3: 格式化图谱三元组

将知识图谱三元组格式化为文本描述：

@staticmethod
def _format_kg_triples(kg_triples: List, char_budget: int) -> Tuple[str, int]:
    formatted_lines = []
    used_chars = 0

**格式化结果示例：**

```

> **图谱三元组与检索文档的区别**：检索文档是原文段落（长文本），图谱三元组是结构化关系（短文本）。两者互补——文档提供详细描述，三元组提供关键关系链，帮助 LLM 更准确地回答结构化问题。

def _invoke_generate(self, llm_client, prompt: str) -> str:
    try:
        response = llm_client.invoke(prompt)
        return response.content
    except Exception as e:
        self.logger.error(f"生成回答出错: {e}")
        return "抱歉，生成回答时出现错误。"
```

> **降级处理**：LLM 调用可能因为 API 超时、token 超限、网络异常等原因失败。`try/except` 捕获所有异常后返回友好错误信息，不会中断整个查询流程。

            response = llm_client.invoke(prompt)

            return "抱歉，生成回答时出现错误。"

### 6.2 节点设计要点

#### 要点 1：字符预算控制

```python
char_budget = self.config.max_context_chars  # 12000

# 依次分配，优先级递减，前一个方法消耗后剩余预算传给下一个
context_str, char_budget = self._format_reranked_docs(docs, char_budget)
graph_str, char_budget = self._format_kg_triples(triples, char_budget)
```

检索文档是核心参考，优先级最高；图谱关系是补充，优先级最低。预算用尽后自动截断，保证提示词不超限。

#### 要点 2：已有答案的处理

```python
if state.get("answer"):
    return state  # 直接返回，跳过 LLM 调用
```

商品确认节点可能已生成澄清提示（如"请问您是指 A 还是 B？"），答案生成节点发现已有答案就直接返回，避免不必要的 LLM 调用。

#### 要点 3：降级与容错

```python
try:
    response = llm_client.invoke(prompt)
    return response.content
except Exception as e:
    self.logger.error(f"生成回答出错: {e}")
    return "抱歉，生成回答时出现错误。"
```

LLM 调用失败不会中断流程，返回友好错误信息。用户看到的是"抱歉..."而不是 500 报错。

#### 要点 4：元信息标签的作用

```
[1] [source=local] [chunk_id=chunk_001] [title=操作指导] [score=5.0600]
测量直流电压时...
```

元信息标签传给 LLM 有两个作用：帮 LLM 判断文档可信度（高分 > 低分，local > web），以及在答案中标注引用来源。
